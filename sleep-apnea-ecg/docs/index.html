Sleep apnea detection from a single ECG lead

When breathing stops during sleep, the heart slows, then races when the sleeper half-wakes. Two neural networks learn to spot that rhythm, one minute at a time, from heartbeat timing alone.

The signal: time between heartbeats

Diagnosing sleep apnea normally takes an overnight lab study with a dozen sensors. A single ECG lead is far cheaper, and it carries a fingerprint of apnea in its RR intervals, the time between consecutive R-peaks.

During an apnea the heart slows; when breathing resumes it speeds up. Repeated every 30 to 90 seconds, that produces a cyclic wave in the RR series. Each minute of the PhysioNet Apnea-ECG database is labelled by experts as apnea or normal, so the task is a per-minute yes/no decision.

Stage 1: a small network on one patient

The first model turns each minute of raw ECG into seven numbers and classifies them with a dense network of 1,161 parameters.

Why 98% is not the real story

Record a01 is a severe apnea patient: 470 apnea minutes against 18 normal. A model that answers "apnea" for every minute already scores 96%. The confusion matrix shows what the extra two points bought.

Three problems stack up. It is one patient, so the network may have learned one person's heart rather than apnea. The classes are badly imbalanced, so accuracy says little. And the split is random over minutes, so neighbouring minutes from the same night sit on both sides of it.

A test set with a handful of normal minutes cannot support a claim about anyone else. Recognising that is what led to Stage 2.

Stage 2: an LSTM across 35 patients

The rebuild fixes all three problems: every record in the database, no hand-made features, and a split that no patient crosses. The LSTM reads each minute's RR intervals in order, so it can learn "slow, then fast" directly, which seven summary statistics cannot express.

The data

Patient-independent split

Records are divided before any minute is touched. No minute from a test patient is ever seen in training. Letters mark the database's own groups: a apnea, b borderline, c control.

The model

Keras Tuner searched layer count, units, activations, dropout and learning rate, scoring each configuration by validation AUC. It settled on the smallest options available: about 11,000 training sequences of a single feature do not support a bigger network.

Pooled numbers hide individuals. Clinically, what matters is the whole night: how many apnea minutes per hour of sleep. Here the model's minute-level calls are added up per patient and set against the expert labels.

Side by side

The LSTM's accuracy looks worse than the ANN's 98%. It is answering a much harder question: not "can it label minutes from a night it has already seen?" but "can it label a person it has never met?" Only the second matters for screening.

Audit: what changed in the rewrite

Re-reading the original notebooks line by line turned up problems that changed the reported numbers. Each one is fixed in the pipeline and covered where possible by a test.

Labels shifted by one minute

The a01 annotation file was read with its first line treated as a header, so minute 0's label disappeared and every window was paired with the next minute's label: 488 labels instead of 489. The rewrite reads labels straight from the database's .apn annotations and keeps each window tied to its own minute.

The retrained LSTM was never evaluated

The notebook retrained best_model but then predicted and evaluated with a different variable, model. The reported 80% accuracy came from that other model, whose AUC was 0.58. Now one object is trained, evaluated, saved and exported, and the export is checked against Keras before it is written.

Class imbalance corrected twice

Training data was undersampled to 50/50 and then given class weights computed from the original 61/39 split, tilting the model toward "apnea" (81% recall, 32% precision). The rewrite keeps all training minutes and applies balanced class weights once.

Smaller fixes

The Stage 1 scaler was fit before the train/test split, so test statistics leaked into training; it is now fit on training rows only. Skipped windows could have desynchronised features and labels; indices are now kept together. The decision threshold is chosen on validation patients instead of fixed at 0.5. A fair ANN baseline (Stage 1b) now uses the same 35-patient split as the LSTM.

Limitations

  • One signal. Only RR intervals are used. ECG-derived respiration from R-peak amplitude is the obvious next input.
  • Few patients. 35 recordings, six in the test set. Any single number here carries wide error bars.
  • Minutes, not diagnoses. Clinical diagnosis uses the apnea-hypopnea index over a whole night from a full sleep study. The per-patient roll-up is an approximation of that, not a substitute.
  • Small search. The hyperparameter search covers a seven-dimensional space with a handful of trials. It finds a reasonable configuration, not the best one.

Run it yourself

One script downloads the database, runs every stage, and writes the files this page reads. Commit them and the site updates.

git clone https://github.com/<you>/sleep-apnea-ecg
cd sleep-apnea-ecg
pip install -r requirements.txt
python scripts/run_pipeline.py          # add --quick for a 3-minute smoke test
python -m pytest                        # fast tests, no GPU or download needed

Data: PhysioNet Apnea-ECG Database (Penzel et al., 2000), via wfdb or the Kaggle mirror.
